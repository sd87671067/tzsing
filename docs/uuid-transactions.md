# UUID 创建事务与连接恢复

新增 UUID 仍受 sing-box 校验、全局配置锁、版本合并、原子写入、真实 UUID 路径探测及失败回滚保护。sing-box 1.13.15 的 `cmd/sing-box/cmd_run.go` 在 SIGHUP 下校验后调用 `cancel()` 和 `instance.Close()`，并重新创建实例；生产 unit 也没有 ExecReload。因此这里保留明确提示的受控重启，不承诺连接无中断。

旧链路在浏览器请求上下文中等待 `/uuid-apply`，应用成功后才写显示名称。浏览器经过同一个 sing-box 时，重启可能断开正在等待的 HTTPS 请求；Web 到控制器的请求上下文随之取消，但控制器可能已经完成配置应用。旧 UI 把响应丢失当作失败，重试会重新预览并生成另一个 UUID。

新链路使用确认 nonce 作为客户端幂等事务 ID，数据库仅存其摘要。二次确认时先将服务器、经控制器预览得到的入站/UUID 身份、显示名称、计划和事务一起持久化，原节点表按 `(server,tag)` 保留 ID。随后返回 HTTP 202，后台执行不依赖浏览器连接。名称不会从 Agent 的自动认证名称推断，也不会修改认证 UUID、Tag、路由或 sbbot 名称。

`GET admin/node-transaction?id=...` 独立查询原事务，仅创建者且仍具备管理员修改权限的会话可访问。控制器的 `/uuid-result` 读取原子落盘回执，不等待配置锁。成功回执在删除配置恢复日志之前写入，控制器重启能区分已提交事务和需回滚的中断事务。相同计划重复应用只返回回执，不再次写配置。未收到回执的网络错误保留 pending，不宣称失败；未解决的回滚冲突标记 uncertain，禁止前端生成新 UUID。

浏览器在发送确认前将事务 ID/服务器保存到当前用户的 localStorage；断网、刷新、重新登录及连接恢复后查询原事务。仅在服务端尚未接收时重发相同确认，不重新预览。每个请求 8 秒上限，轮询 3 分钟后解除等待并提示结果尚未确认，保留原 ID；在线、切回页面或“查询原添加事务”可继续确认。已有未决事务时禁止另行提交。成功自动请求 snapshot，后续 Agent 报告通过已有 WebSocket 更新卡片。

显示优先级沿用 Store.Present：个人别名、管理员名称、原始名称、默认兜底；Agent 发现使用 INSERT OR IGNORE，不覆盖名称。已有节点不按名称/IP/出站合并。普通卡片仅保留用户可理解的停用/到期/额度状态，不展示崩溃预留说明及未结算预留字样；底层预留扣减、审计和详情诊断保留。

正式验证必须在操作者指定的 `sd87671067/go-emby-test` 工作树内进行。本项目可放在该工作树的独立子目录。真实 REALITY/443 验证必须使用新 network namespace 和合成密钥/UUID；不得在生产新增测试身份。部署前备份 SQLite、配置、旧镜像及控制器二进制；只更新 Web 和控制器，不为发布重启 sing-box 或 sbbot。

## 定向验收（2026-11-03）

恢复现场的源码与远端 main 均为 effd1d2；原有未提交实现保留。正式验证位于 sd87671067/go-emby-test 工作树内的 tzsing-under-test 子目录，未执行全量或 race。

- 控制器回执：丢弃应用响应，重建控制器后查询并重放三次；成功只激活一次，失败恢复原字节，状态查询不被应用锁阻塞。
- Web 恢复：Unix HTTP 连接在应用成功后直接关闭；相同 nonce 重复请求不重复创建。关闭重开 SQLite、丢失 Web 内存确认与任务后，查询仍派发原计划并保留名称。WebSocket 返回两个独立身份及其各自名称。
- WebKit：390/1440 两个视口真实登录，服务端接收请求后丢弃浏览器响应，注入两次查询 503，再刷新恢复；每次创建请求数为 1，ck 可见，loading 结束，普通卡片无内部预留说明。原 Chromium 390/1440 成功记录保留。新增 Chromium 手机用例覆盖取消、预览失败、应用失败、三分钟超时和恢复，不重复提交。
- REALITY：独立 network namespace 内的 TCP 443 + Vision，合成密钥与 UUID；真实连接验证出口、身份隔离、创建重放、共享密钥和监听保持，以及启动/健康失败回滚。完整执行 129.40 秒，退出码 0。旧 90 秒限制不足，编译时间也不能计入真实测试预算；改为先编译，子进程 150 秒、Go 测试 160 秒、外层 170 秒并清理自身子进程。
- 配置校验失败、应用失败、健康失败及应用后探测失败分别验证原配置保持或自动恢复。以上最终定向测试退出码均为 0；早期超时及失败日志保留，不作为通过证据。
