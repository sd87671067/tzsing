# Configuration confirmations

Outbound creation/edit/deletion and inbound route/control apply now retain the original preview confirmation ID in browser localStorage and a `config_operations` intent in SQLite before dispatch. The controller writes `apply-result-<plan digest>.json` before mutation and commits its success receipt before removing `transaction.json`. Replays return the original receipt and do not activate sing-box again.

`GET control/transaction?id=<confirmation>` is authenticated, restricted to its owner, uncached, and bypasses the Web mutation lock. Controller receipt reads also bypass the apply lock. Lost HTTP responses, timeout, 5xx and disconnection remain pending; they never establish failure. The browser releases form loading after its bounded request, retains the original intent, and polls with backoff, resuming on online, visibility and authenticated monitor reconnection. Only a missing Web intent permits replay of the same ID. It never generates another preview or resubmits new configuration. Terminal receipts determine success/failure. Uncertain rollback retains the operation for recovery/manual inspection. Existing UUID create receipts and rollback journals remain compatible.

The optional outbound TAG is sent as `node.create_tag`, separate from the existing edit target `node.tag`. New tags cannot overwrite existing tags anywhere in the configuration; blank preserves automatic generation. Display aliases remain in SQLite.

The add-inbound form adds a UUID user to an existing VLESS REALITY listener. Its optional NAME is `node.auth_name`, stored in supported `users[].name`, never an unsupported listener-level `name`. Blank preserves generated authentication names. NAME is distinct from the display alias; duplicate/control-character names are rejected. Existing UUIDs, listener tags, keys and port 443 are preserved. The regular monitor intentionally redacts authentication names; rediscovery reads them from the supported identity configuration.
