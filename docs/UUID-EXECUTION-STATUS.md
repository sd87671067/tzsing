# UUID 执行状态（2026-11-01 本轮接续）

生产逐 UUID 实时流量继续使用认证身份/精确路由观测；它不是完整计费账本。UUID/name 路由与实际出站 IP 分别维护，出口共享不会合并不同 UUID 的流量。

## 出口恢复

探针不再依赖旧静态哈希。只读监督器核对生产服务 PID、准确配置参数、配置 ctime 早于进程启动、运行二进制一致，再用相同出站和 DNS/默认解析器构建独立的本机认证 SOCKS 探针。配置、进程、凭据或选择器变化会使旧路径/缓存失效；无法证明已应用的磁盘编辑保持拒绝检测。没有修改生产监听、鉴权或路由。

基础 ipify HTTPS IP 先发布，IPinfo/IPPure 后台补充并缓存；异步结果再次检查配置、出口凭据和 IP，不能附着到变化后的路径。交互检测同样使用服务端 UUID → 当前路由 → 实际 Tag 的证明，不提供默认出口回退。

本轮真实只读检测：7 个实际出站中 6 个 IPv4 成功，另 1 个中转 HTTPS 超时，IPv6 无成功结果。真实端点、地址、凭据仅保留于服务器受限审计目录，不随公共代码发布。

## 隔离数据路径候选

`policy/` 和 `scripts/build-policy-singbox.py` 只供独立的 sing-box v1.13.15 候选验证。账本按入站与 UUID 稳定摘要索引，原始 metadata.User、TLS/REALITY、客户端协议和 auth_user 路由不改。当前集成依赖 Clash tracker 被启用；尚未覆盖所有协议路径，不能作为生产认证执行器。

SQLite 使用 WAL、FULL synchronous 和 BEGIN IMMEDIATE，实际结算、方向计数与未决预留分别记录；相同结算幂等，冲突结算拒绝。预留不作为已用流量显示，也不在崩溃后自动假定已发送或未发送。未决项只阻止受影响 UUID 继续准入。
